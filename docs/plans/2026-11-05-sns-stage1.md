# SNS Stage 1 — synapse-client-sdk (F4) — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Sostituire l'integrazione SNS basata sul proxy REST deprecato (worker rimosso lato SNS — `sns-sdk-proxy.bonfida.workers.dev` risponde 404/1042 con **nessun worker in servizio**) con reader on-chain locali funzionanti su **web3.js 3.1.1** (installata), e ripristinare il display `.sns`.

**Architecture:** Il proxy REST muore e NON si ripristina. Due opzioni di write e una di read:
- **READ (primaria):** portare i reader di derivazione/decodifica SPL Name Service già funzionanti in `sap-mcp/packages/tools/src/sap-sns-tools.ts` (pattern zero-dep, adattati a web3 3.x).
- **WRITE (register)**: builder via **nuova REST proxy ufficiale SNS** (self-hostable da `sdk-proxy/` nel monorepo `SolanaNameService/sns-sdk`) con URL configurabile via env — è agnostico tra le generazioni di web3.js (ritorna istruzioni raw JSON / tx base64). Il codice `executeSns` ha già lo stesso pattern.
- js-kit v1 (`@solana-name-service/sns-sdk-kit@1`): **scartata come percorso primario** — peer `@solana/kit ^6.9.0` ≠ kit 8 usato da web3.js 3.x, engines node ≥ 24.

**Tech stack:** `@solana/web3.js 3.1.1` (già installata), pnpm.

**Branch:** `feat/sns-stage1` da `development @ 5277bfb` (verificato 05-11: `origin/development` appena creato == main, delta 0/0). PR → `development`; il vecchio `origin/develop` (divergato 15/11) va ignorato come linea di integrazione.
